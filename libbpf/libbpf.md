## libbpf

### 兼容性的问题
- kernel 数据结构的变化
- field 被重命名
- kconfig编译打开和关闭某些feature，导致某些field缺失
#### BCC 如何解决的
- 将C代码的BPF程序作为string embed到用户态的程序中
- 在最终的目标机器上利用LLVM和本机的kernel header file 编译出正确的版本
问题:
- Clang/LLVM combo is a big library, resulting in big fat binaries
- Clang/LLVM combo is resource-heavy,在生产机器上编译会影响生产机器的性能，编译也比较慢
- 目标机器可能没有相应的编译环境(header file)

### CO-RE
- BTF type information
- compiler (Clang)
- BPF loader (libbpf) ties BTFs from kernel and BPF program together to adjust compiled BPF code to specific kernel on target hosts;
- kernel provides advanced BPF features to enable some of the more advanced scenarios
#### BTF
BTF (BPF Type Format) was created as an alternative to a more generic and verbose DWARF debug information
https://www.kernel.org/doc/html/latest/bpf/btf.html
BTF 文件描述了数据类型的name，type和offset信息
guide：https://nakryiko.com/posts/bpf-core-reference-guide/

``` minimal.bpf.c
// SPDX-License-Identifier: GPL-2.0 OR BSD-3-Clause
/* Copyright (c) 2020 Facebook */
#include <linux/bpf.h>
#include <bpf/bpf_helpers.h>

//Sec() 为 eBPF 程序或数据结构指定 ELF 段（Section）名称
// SEC() 宏会扩展为 __attribute__((section("section_name")))，指示编译器将代码或数据放置在 ELF 文件的指定段中。

char LICENSE[] SEC("license") = "Dual BSD/GPL";

int my_pid = 0;

SEC("tp/syscalls/sys_enter_write")
int handle_tp(void *ctx)
{
        //get the PID (or "TGID" in internal kernel terminology)
        // encoded as the upper 32 bit
	int pid = bpf_get_current_pid_tgid() >> 32;

	if (pid != my_pid)
		return 0;

        // send the output to /sys/kernel/debug/tracing/trace_pipe
	bpf_printk("BPF triggered from PID %d.\n", pid);

	return 0;
}

```
- compile bpf.0: clang -O2 -target bpf -c example.bpf.c -o example.bpf.o

``` minimal.c
// SPDX-License-Identifier: (LGPL-2.1 OR BSD-2-Clause)
/* Copyright (c) 2020 Facebook */
#include <stdio.h>
#include <unistd.h>
#include <sys/resource.h>
#include <bpf/libbpf.h>
#include "minimal.skel.h"

static int libbpf_print_fn(enum libbpf_print_level level, const char *format, va_list args)
{
	return vfprintf(stderr, format, args);
}

int main(int argc, char **argv)
{
	struct minimal_bpf *skel;
	int err;

	/* Set up libbpf errors and debug info callback */
	libbpf_set_print(libbpf_print_fn);

	/* Open BPF application */
	skel = minimal_bpf__open();
	if (!skel) {
		fprintf(stderr, "Failed to open BPF skeleton\n");
		return 1;
	}

	/* ensure BPF program only handles write() syscalls from our process */
	skel->bss->my_pid = getpid();

	/* Load & verify BPF programs */
	err = minimal_bpf__load(skel);
	if (err) {
		fprintf(stderr, "Failed to load and verify BPF skeleton\n");
		goto cleanup;
	}

	/* Attach tracepoint handler */
	err = minimal_bpf__attach(skel);
	if (err) {
		fprintf(stderr, "Failed to attach BPF skeleton\n");
		goto cleanup;
	}

	printf("Successfully started! Please run `sudo cat /sys/kernel/debug/tracing/trace_pipe` "
	       "to see output of the BPF programs.\n");

	for (;;) {
		/* trigger our BPF program */
		fprintf(stderr, ".");
		sleep(1);
	}

cleanup:
	minimal_bpf__destroy(skel);
	return -err;
}

```

### makefile
``` 1 step
# Build libbpf
$(LIBBPF_OBJ): $(wildcard $(LIBBPF_SRC)/*.[ch] $(LIBBPF_SRC)/Makefile) | $(OUTPUT)/libbpf
	$(call msg,LIB,$@)
	$(Q)$(MAKE) -C $(LIBBPF_SRC) BUILD_STATIC_ONLY=1		      \
		    OBJDIR=$(dir $@)/libbpf DESTDIR=$(dir $@)		      \
		    INCLUDEDIR= LIBDIR= UAPIDIR=			      \
		    install
```

- use Clang to do this. -g is mandatory to make Clang emit BTF information.
- -D__TARGET_ARCH_$(ARCH) defines necessary macro for bpf_tracing.h header dealing with low-level struct pt_regs macro.
```2 strop
# Build BPF code
$(OUTPUT)/%.bpf.o: %.bpf.c $(LIBBPF_OBJ) $(wildcard %.h) vmlinux.h | $(OUTPUT)
	$(call msg,BPF,$@)
	$(Q)$(CLANG) -g -O2 -target bpf -D__TARGET_ARCH_$(ARCH) $(INCLUDES) -c $(filter %.c,$^) -o $@
	$(Q)$(LLVM_STRIP) -g $@ # strip useless DWARF info
```

``` 3 step
# Generate BPF skeletons
$(OUTPUT)/%.skel.h: $(OUTPUT)/%.bpf.o | $(OUTPUT)
	$(call msg,GEN-SKEL,$@)
	$(Q)$(BPFTOOL) gen skeleton $< > $@
```

```4 step
# Build user-space code
$(patsubst %,$(OUTPUT)/%.o,$(APPS)): %.o: %.skel.h

$(OUTPUT)/%.o: %.c $(wildcard %.h) | $(OUTPUT)
	$(call msg,CC,$@)
	$(Q)$(CC) $(CFLAGS) $(INCLUDES) -c $(filter %.c,$^) -o $@
```

```5 step
# Build application binary
$(APPS): %: $(OUTPUT)/%.o $(LIBBPF_OBJ) | $(OUTPUT)
	$(call msg,BINARY,$@)
	$(Q)$(CC) $(CFLAGS) $^ -lelf -lz -o $@
```

#### Dealing with kernel version and configuration differences
```
extern u32 LINUX_KERNEL_VERSION __kconfig;
extern u32 CONFIG_HZ __kconfig;

u64 utime_ns;

if (LINUX_KERNEL_VERSION >= KERNEL_VERSION(4, 11, 0))
    utime_ns = BPF_CORE_READ(task, utime);
else
    /* convert jiffies to nanoseconds */
    utime_ns = BPF_CORE_READ(task, utime) * (1000000000UL / CONFIG_HZ);
```

#### type cast to a struct flavor 
- struct thread_struct___v46. Three underscores in type name and everything after it are considered to be a “flavor” of this struct. 
- This flavor part will be ignored by libbpf
```
/* up-to-date thread_struct definition matching newer kernels */
struct thread_struct {
    ...
    u64 fsbase;
    ...
};

/* legacy thread_struct definition for <= 4.6 kernels */
struct thread_struct___v46 { /* ___v46 is a "flavor" part */
    ...
    u64 fs;
    ...
};

extern int LINUX_KERNEL_VERSION __kconfig;
...

struct thread_struct *thr = ...;
u64 fsbase;
if (LINUX_KERNEL_VERSION > KERNEL_VERSION(4, 6, 0))
    fsbase = BPF_CORE_READ((struct thread_struct___v46 *)thr, fs);
else
    fsbase = BPF_CORE_READ(thr, fsbase);
```
#### file struct
- <app>.bpf.c files are the BPF C code that contain the logic which is to be executed in the kernel context;
- <app>.c is the user-space C code, which loads BPF code and interacts with it throughout the lifetime of the application;
- optional <app>.h is a header file with the common type definitions and is shared by both BPF and user-space code of the application.

### Step
https://nakryiko.com/posts/libbpf-bootstrap/

https://facebookmicrosites.github.io/bpf/blog/2020/02/20/bcc-to-libbpf-howto-guide.html
Building libbpf-based BPF application using BPF CO-RE consists of few steps:
1. generating vmlinux.h header file with all kernel types;
2. compiling your BPF program source code using recent Clang (version 10 or newer) into .o object file;
3. generating BPF skeleton header file from compiled BPF object file;
4. including generated BPF skeleton header to use from user-space code;
5. then, at last, compiling user-space code, which will get BPF object code embedded in it, so that you don’t have to distribute extra files with your application.
